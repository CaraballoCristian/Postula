# 🚀 Postulá — Job Application Manager

Full-stack web application for managing **job applications end-to-end**, built with **Angular 19 and Node.js/Express**.  
Designed to **automate personalized application messages** (recruiter email, company message, employee contact), **track the full history** of every application and **visualize your activity** on a Bento-style dashboard.

Built as a **monolithic app** (single container serves the API + the built client), with a **PWA installable frontend**, multi-user **JWT authentication + Google OAuth**, and a **local-first SQLite** backend.

## 🗄️ Database Setup

The schema is **auto-generated by versioned migrations** on startup (`db.ts`).  
No manual table creation is needed — a fresh SQLite database is created and migrated automatically.

The data is stored in a volume at `/app/data/postulatool.sqlite` (production) or `server/data/postulatool.sqlite` (local dev).

> **Schema evolution**: migrations are tracked via SQLite `PRAGMA user_version`. Each migration is idempotent (structural guards: `hasColumn`, `hasCheck`) and applied once inside a single transaction.

## 🚀 Installation & Setup

### Docker (recommended)

```bash
# Clone the repository
git clone https://github.com/CaraballoCristian/Postula.git

cd Postula

# 1. Configure secrets (copy the example)
cp .env.example .env
# then fill GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET / JWT_SECRET
# optional: CORS_ORIGINS (comma-separated allowed origins, e.g. https://tu-dominio.com)

# 2. Build and start
docker compose up -d --build

# 3. Open in browser
http://localhost:3033
```

> The container builds the Angular client and compiles the TypeScript server, then runs a single Express process that serves both the `/api` endpoints and the built SPA.

### Local development

```bash
# Backend (hot-reload)
cd server
npm install
npm run dev          # http://localhost:3000

# Frontend (separate terminal)
cd client
npm install
npm start            # http://localhost:4200 (proxies /api to :3000)
```

## 🔐 Authentication Flow

1. **Register / login with email + password** → `POST /api/auth/register` / `POST /api/auth/login`
2. **Or log in with Google** → `GET /api/auth/google` (redirects to Google; callback signs a JWT and returns to the app)
3. **Use the returned token** → `Authorization: Bearer YOUR_TOKEN`

> Google accounts are **linked by email**: if the Google email already has a local account, it signs into that account (password untouched); otherwise a new account is created and seeded.

## ✨ Features

- 🔐 **Multi-user authentication** — JWT + Google OAuth (linked by email)
- 📊 **Bento dashboard** — streak, total, *vs. previous period*, trend chart, **status distribution donut (always global)**, distribution by category and language; filters (today/week/month/all + custom range)
- ✉️ **Template-driven message generation** — email, company message and recruiter message from reusable `{placeholder}` templates
- 🌍 **Multi-language & multi-category templates** — tone per role (Tech, Management) and language (ESP/ENG)
- 📋 **Filterable application history** — search, sort, filter by category, language and status tag
- 🏷️ **Custom status tags** — create, rename (with propagation) and delete (with mandatory reassignment); real FK to `tags`
- 🗃️ **View modes** — table and grouped-by-company
- 🔄 **Bulk status updates** — change the status of multiple applications at once
- 🗑️ **Trash (soft delete)** — restore or permanently purge
- 💾 **Backup / Restore** — export the data as JSON; restore brings the history (postulaciones) plus its categorias/templates/idiomas. **`config` (personal data) and `tags` are never imported**, preventing duplicates; postulacion statuses are kept when the tag already exists, otherwise remapped to the account's default tag.
- 📎 **One-click copy** — copy individual or all generated messages at once
- 📱 **Progressive Web App (PWA)** — installable, offline asset caching, auto-update prompt
- 🌐 **Web / PWA view toggle** — choose a centered reading frame or fullscreen (Notion-style)
- 🎨 **Dark/light theme + custom accent color**
- 🌍 **Internationalization** — Spanish / English
- 🔤 **Typography** — Inter (UI), Manrope (secondary), Space Grotesk (logo), all **self-hosted**
- 🛠️ **Versioned DB migrations** — idempotent, tracked via `user_version` (with a repair routine for a legacy column-shift bug)

## ⚠️ Note

- **Security**: the server mounts [Helmet](https://helmetjs.github.io/) (security response headers; CSP disabled to allow the SPA's inline styles) and a **restrictive CORS** whitelist driven by the `CORS_ORIGINS` env var (defaults to `http://localhost:4200,http://localhost:3033` for local dev). In production set `CORS_ORIGINS=https://tu-dominio.com` (comma-separated for multiple origins). The app uses `trust proxy: 1`, so it must sit behind **one** trustable proxy (e.g. a reverse proxy that terminates HTTPS); adjust if you add Cloudflare/Traefik hops.

Frontend build budget warning: the initial bundle exceeds **500 kB** (currently ~576 kB, warning is non-blocking). If you want to silence it, raise or remove the `maximumWarning` budget in `client/angular.json`.

The Google OAuth flow uses a **cookie-based `state`** (httpOnly) to prevent CSRF and only accepts accounts with a **verified email** (`email_verified`). Credentials are read from environment variables (`GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`) — never commit the `.env` file.
